# 数据格式与恢复

## 保存位置与备份

默认目录为 `~/Library/Application Support/PromptPin`，包含主资料 `library.json` 和上一版自动备份 `library.backup.json`。设置菜单中的“打开数据文件夹”可以直接定位目录。

两者均为明文 JSON，可能包含密码、SK、API Key 或私钥。不要把它们作为示例文件提交或附在公开 Issue 中。导出的 `PromptPin-<日期>.json` 同样包含完整资料。

数据独立于源码和应用包。退出应用、重新构建或替换应用包不会清除资料。若磁盘资料已被其他进程修改，保存会报错并保留编辑内容，避免覆盖新的磁盘资料。

## 字段与分类

- **账号关系**：未指定、不区分主子账号、主账号 / 根账号、子账号 / IAM 用户、服务账号 / 机器身份。
- **用途**：云平台、对象存储 / 存储桶、网站 / 应用、大模型 / AI、数据库、服务器 / SSH、代码托管 / CI、企业平台、其他 / 自定义。
- **凭据格式**：AK/SK、API Key、Token / Bearer Token、SSH 私钥、证书 / 私钥、连接字符串和其他凭据。

账号关系与用途均可不填。账号密码只要求名称和密码；AK/SK 只要求名称、AK 和 SK；其他密钥格式要求名称和密钥文本。保存证书、私钥或连接字符串只表示保存文本，不进行解析或连接。

## 旧资料兼容

版本 1 资料可以由当前应用读取。旧主账号、子账号、密码、密钥、ID 和时间会保留，新增分类默认为“未指定”。历史记录中放在主 / 子账号栏的地址或资源也会保留，不会自动改写为其他字段。

打开应用不会直接改写旧文件；首次主动保存时写入版本 2，并保存上一版备份。旧应用会拒绝版本 2，避免忽略新增字段后覆盖资料。切换密钥格式不会清空其他格式的已有字段。

## 导入与损坏恢复

导入按 UUID 合并：已有项目、提示词、账号、密钥和备忘录保留，新记录加入；相同 ID 的记录不会被导入内容覆盖，重复导入同一份文件不会增加重复记录。

主文件损坏或版本未知时，应用会停止编辑和写入。恢复上一版前，会将损坏的原文件另存为 `library.unreadable-<UUID>.json`。该副本也可能含敏感资料，应按原文件同等保管。

自动备份仅保留上一版有效资料，不是完整历史。请通过导出功能自行安排长期备份。

## 只读兼容检查

如需确认已有资料可以无损解码和重新编码，可运行以下命令。它会读取完整资料但不会输出记录内容或改写原文件：

```bash
swift run PromptPinCoreChecks "$HOME/Library/Application Support/PromptPin/library.json"
```

如需兼容工具链，请改用 `PROMPT_PIN_COMPAT=1 ./scripts/swift.sh run PromptPinCoreChecks`，并传入同样的路径参数。常规开发检查无需访问真实资料，请优先运行不带路径参数的检查。
